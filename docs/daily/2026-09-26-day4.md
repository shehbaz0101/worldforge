# Day 4 — 2026-09-26

One-step training loop for Project B. America/New_York date for this note.
No planner, multi-horizon eval suite, or HTTP API.

## Shipped

- `src/worldforge/train/`: `train_world_model` fits a `WorldModel` on stored
  transitions. Batches come from Day 2 `sample_transition_batch`. The
  objective is one-step observation MSE plus
  `reconstruction_weight *` reconstruction MSE. The default weight is 1.
  Weight 0 trains the prediction term only. The optimizer is Adam or SGD.
  The device is `cpu`.
- A run is deterministic for a model init seed and a `TrainConfig` seed.
  Batch seed is `seed + epoch * 1000003 + step` (both indexes zero-based).
  The default steps per epoch are `ceil(transitions / batch_size)`. During
  the run the intra-op thread count is 1 and MKLDNN is disabled when
  present; threads, MKLDNN, and the CPU generator state are restored.
- Checkpoint directory stays `worldforge.checkpoint.v1`: `config.json` and
  `weights.pt`, with no optimizer state. The trainer also writes
  `metrics.jsonl` (one epoch object per line) and `train.json`
  (`worldforge.train.v1`). `load_checkpoint` ignores those extra files.
  `final_train_loss` is the last epoch's mean step loss.
- CLI: `worldforge train` with `--data`, `--out`, `--epochs`, `--batch-size`,
  `--lr`, `--seed`, `--device` (cpu only), plus `--recon-weight`,
  `--steps-per-epoch`, and `--optimizer`. `--seed` initializes the weights
  and selects replay batches. Dataset commands still import without torch.
- Defaults on the golden fixtures are 3 epochs, batch size 8, and 6 steps
  per epoch. That run finishes in a few seconds on CPU.
- Tests train for 2 or 3 optimizer steps on the fixtures, check a finite
  loss, reload the checkpoint, and compare two seeded runs (same final loss
  and same weights). A different replay seed changes both. Nothing is marked
  `integration`.
