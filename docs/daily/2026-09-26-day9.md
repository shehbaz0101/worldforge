# Day 9 — 2026-09-26

A one-command offline demo and a tiny checked-in corpus, so a newcomer
can run collect-train-predict-plan without inventing paths.
America/New_York date for this note. WorldForge stays offline. No
authentication.

## Shipped

- `worldforge demo`. It trains a small CPU checkpoint, scores an open-loop
  rollout, plans one action sequence, and writes closed-loop regret. The
  libraries are the Day 4 trainer, the Day 5 eval, and the Day 6 planner.
  The printed summary lists `final_train_loss`, per-horizon MSE,
  `plan_predicted_return`, and `regret`. The same text is `summary.txt`.
- Output layout under `--out` (default `demo-run/`): `checkpoint/`,
  `predict.json`, `plan.json`, `eval-plan.json`. Reports stay
  `worldforge.predict.v1`, `worldforge.action_sequence.v1`, and
  `worldforge.plan.v1`.
- `samples/demo.json` (`worldforge.demo.v1`) and `samples/trajectories/`.
  Two episodes, horizon 4: seed 0 `zero`, seed 1 `random`. The demo uses
  that directory when it is inside the data root. Otherwise it copies the
  files under the output directory. If the samples are missing it collects
  the same episode list there. Regenerate with
  `python scripts/regenerate_samples.py`.
- Caps match the HTTP trainer: at most 5 epochs and 8 steps per epoch.
  Defaults are 1 and 1, latent width 4, hidden width 16, plan horizon 2,
  4 CEM samples, 1 iteration, 2 closed-loop steps. `--seed` fixes weights,
  replay, CEM, and the environment together. `--device` is `cpu` only.
- Day 8 sandbox: `--data-root` / `WORLDFORGE_DATA_ROOT`. `--out` and
  `--data` must stay inside it. After torch imports, the command installs
  the offline socket guard. A missing `ml` extra exits with the same
  `pip install -e ".[ml]"` hint as `worldforge train`.
- Docs: this note, `PROJECT_STATUS.md`, the README demo section, and
  `docs/architecture.md`. `demo-run/` is gitignored.
