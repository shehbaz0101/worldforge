# Day 2 — 2026-09-26

Offline trajectory corpus for Project B. America/New_York date for this note.
No encoder, dynamics model, trainer, planner, or HTTP API.

## Shipped

- `src/worldforge/data/`: `collect_corpus` rolls `lotka_volterra` and writes
  a directory. Parameters are episode count or an explicit seed list,
  horizon, policy, and output formats. Policies are `zero`, seeded `random`,
  and `sine_dose` (open-loop, period 16 steps, quadrature phases, clipped to
  the action bounds). `EpisodeSpec` builds a mixed-policy corpus.
- Corpus layout, format `worldforge.corpus.v1`: `manifest.json`, optional
  `corpus.jsonl` (one trajectory JSON object per line), optional
  `episodes/ep_XXXX.json`. This corpus JSONL is separate from the Day 1
  single-episode JSONL (`record: meta`, then one transition per line).
  `load_corpus` reads a directory, either JSONL shape, or one JSON file.
- `split_trajectories` partitions train, val, and test. Counts use the
  largest-remainder method. Membership shuffles a canonical episode order
  with `random.Random(seed)`, so the split does not depend on input order.
- `sample_transition_batch` draws a deterministic uniform replay batch from
  stored transitions. It does not step the environment and it does not
  update parameters.
- CLI: `worldforge collect` and `worldforge dataset-info`. `env-demo` accepts
  `sine_dose`.
- Golden fixtures in `tests/fixtures/trajectories/`: 6 episodes, horizon 8,
  seeds 0–5, policies zero, random, and sine_dose. `scripts/regenerate_fixtures.py`
  rewrites them. CI loads the committed files.
- Tests cover round-trip load, split determinism, replay-batch determinism,
  fixture agreement with a fresh rollout, and CLI smoke. No test uses the
  network. Nothing is marked `integration`.
